# Specs

Long-running work that spans multiple sessions lives here.

Specs are not a second backlog. They define the goal, scope, constraints, and completion criteria for a program that is too large for a single ticket. Execution still lives in `AVAILABLE_TICKETS.md` and the related files in `project-os/tickets/`.

| `S-001` | Project OS English agent ecosystem | Done |
| `S-002` | Monolith redesign migration (ADR-052, ADR-053) | Open |

## Rules

* Use a spec only for multi-session work.
* Keep ticket IDs in the ticket files.
* Keep status updates in `PROJECT_STATE.md` and `AVAILABLE_TICKETS.md`.
* Do not duplicate product baselines from `product-discovery/`.
