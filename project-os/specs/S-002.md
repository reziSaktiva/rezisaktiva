# S-002 — Monolith Redesign Migration

## Status

Open — started 2026-11-17 · tickets T-075 through T-086

## Decision

[ADR-052](../decisions/ADR-052-monolith-editorial-design.md) adopts the Monolith editorial design as the single public design. [ADR-053](../decisions/ADR-053-redesign-migration-integration-branch.md) sets how it reaches production: integration branch `redesign/monolith`, Vercel Preview as staging, one cutover.

## Goal

Replace the live gothic / blood identity with the Monolith design from `design-mockups/` (v5) without disturbing production, then cut over once, with bilingual copy approved surface by surface.

## Scope

- Docs and agent rules aligned with the redesign (T-075).
- Vercel Preview safety and a production performance baseline (T-076).
- Boss Rezi's decisions on the surfaces the mockup leaves open (T-077).
- Design foundation, chrome, and motion system on the branch (T-078, T-079).
- Surfaces: Home, Work and case, Workflow, Contact page (T-080 to T-083).
- Approved ID / EN copy per surface (T-084).
- Quality gates, dead-code removal, SEO (T-085) and cutover (T-086).

## Out of Scope

- A second design or a visitor-selectable theme (rejected in ADR-052).
- New product features beyond what the mockup and ADR-052 describe (CMS, blog, CV download, calendar, pricing).
- New animation or 3D libraries. Motion and Lenis are already dependencies; the contour field is custom WebGL.
- Changing `COMPLETE_TASK.md` or reopening closed tickets.
- Any redesign code on `main` before cutover.

## Constraints

- Production (`main`) is untouched until T-086. Docs, ADRs, specs, tickets and `design-mockups/` may land on `main` (ADR-051 skips the build).
- Code work goes through one pull request per ticket (or per surface) into `redesign/monolith`. CI and a Vercel Preview run on each.
- Copy is not locked by the mockup. A surface PR does not merge until its copy subtask in T-084 is approved by Boss Rezi in both languages.
- Facts for projects come from `content/data/projects.json` and the resume (ADR-045, ADR-046).
- Next.js in this repo has breaking changes: read the relevant guide in `node_modules/next/dist/docs/` before writing code (see `AGENTS.md`).
- Follow `.cursor/rules/shadcn.mdc`, `code-discipline.mdc` (Server / Client, SSG), `motion.mdc`, and `no-ai-attribution-git.mdc`.
- Merge `main` into `redesign/monolith` at least weekly and before each wave.

## Suggested Order

| Wave | Tickets | Where | Notes |
| ---- | ------- | ----- | ----- |
| A | T-075, T-076 | `main` (docs), Vercel dashboard | No code risk. Unblocks agents and previews. |
| B | T-077 | chat, then ADRs / ticket notes | Boss Rezi decides. Blocks the surfaces it touches. |
| C | T-078, then T-079 | `redesign/monolith` | Foundation first. Chrome needs tokens. |

## Completion Criteria

- Every surface is on the branch, matches the approved mockup behavior, and has approved ID and EN copy.
- The ADR-052 quality gates pass on the branch Preview, including a comparison with the production baseline from T-076.
- T-086 is done: `main` is updated through one approved pull request, production is smoke-checked, the integration branch is deleted, `design-mockups/` is back to archive, and ADR-029 and ADR-031 are marked historical.
