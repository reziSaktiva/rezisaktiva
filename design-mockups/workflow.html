The way I work

On the
record

  • Baseline first

    Business, UX and architecture are settled before code. Big changes go through a new ADR.

  • Every call gets an ADR

    Decision, reason, alternatives. Old plans are superseded, not erased.

  • AI in parallel, me in charge

    I break it down, design it and review it. Agents carry out the tasks side by side.

  • Live code is the truth

    After release, production is the reference for what the product looks like and does.

House rules

Five rules
I keep

01

Decide what, then how

What gets built is settled first — business, UX and architecture — as a baseline. Code follows those documents, not the other way round.

02

Smallest honest scope

An MVP is the leanest version that still tells the story. When scope changes, it changes through a new ADR, not a throwaway message.

03

Keep the reasoning

Each material call records the decision, the reason and the alternatives. Superseded plans stay readable.

04

I lead, agents execute

I break the problem down, design the architecture and review the result. Agents work in parallel. They speed things up; accountability stays with me.

05

Live beats draft

Once it ships, the production code is the reference, not an old mockup. The next iteration starts from what people actually use.
